# PhishWatcher

**Design and Implementation of a Behavioural Anomaly Detection System for Internal Email Impersonation**

PhishWatcher is a research prototype that detects **Business Email Compromise (BEC) / internal impersonation** by fusing two independent signals — a sender's **behavioural** patterns (who they usually email, when, and how the organisation's communication network is shaped) and their **stylometric writeprint** (how they write) — into a single anomaly score. It is built and evaluated on the [Enron email corpus](https://www.cs.cmu.edu/~enron/) as a stand-in for a real internal mail archive.

The project was built to answer two research questions:

- **RQ1** — Does fusing behavioural and stylometric detection outperform either signal used alone?
- **RQ2** — Is the fused approach operationally feasible for near-real-time use (profile-building offline, scoring an incoming email quickly)?

A live dashboard is included so an email can be submitted and scored interactively, alongside an offline evaluation pipeline that reports precision/recall/F1/ROC-AUC against a labelled, semi-synthetic test set.

## How it works

```
Raw Enron CSV
      │
      ▼
┌─────────────────┐      ┌──────────────────────┐
│  Data pipeline   │ ───▶ │   SQLite database     │
│  (parse & clean) │      │  emails + recipients   │
└─────────────────┘      └──────────┬───────────┘
                                     │
                     ┌───────────────┼───────────────┐
                     ▼                                ▼
        ┌────────────────────────┐      ┌─────────────────────────┐
        │  Behavioural profiles   │      │   Stylometric writeprints │
        │  (recipients, timing,   │      │   (function words, n-grams,│
        │   network centrality)   │      │   readability, per-sender  │
        └────────────┬────────────┘      │   mean/std vectors)        │
                     │                    └─────────────┬─────────────┘
                     └──────────────┬─────────────────────┘
                                    ▼
                        ┌───────────────────────┐
                        │   Ensemble detector     │
                        │  (weighted fusion of     │
                        │   4 component scores)    │
                        └───────────┬─────────────┘
                                    ▼
                     Composite anomaly score + risk level
                                    ▼
                    ┌───────────────────────────────┐
                    │  Flask dashboard  /  batch eval  │
                    └───────────────────────────────┘
```

The ensemble combines four component scores for every scored email:

| Component | Signal | Method |
|---|---|---|
| Recipient anomaly | Is this recipient unusual for this sender? | Historical frequency / network relationship analysis |
| Temporal anomaly | Is the send time unusual for this sender? | Per-sender time-of-day / day-of-week baseline |
| Behavioural anomaly | Network-relationship anomaly | NetworkX communication graph, centrality & edge history |
| Stylometric anomaly | Does the writing match the claimed sender? | Per-user z-score + population Isolation Forest over writeprint vectors |

A weighted composite score is thresholded into `NORMAL` / `LOW` / `MEDIUM` / `HIGH` / `CRITICAL` risk levels.

Because Enron doesn't contain labelled impersonation attempts, test cases are generated by an **impersonation simulator** that builds genuine style-swapped, behaviour-swapped, and fully-swapped examples from real historical emails (rather than synthetic filler text), so the evaluation reflects the actual detectors rather than an easy synthetic signal.

## Getting started

### Prerequisites

- Python 3.10+
- The [Enron email dataset](https://www.cs.cmu.edu/~enron/) (or a compatible CSV with `from`/`to`/`date`/`subject`/`body` columns, or raw RFC822 `content`)

### Installation

```bash
git clone <repository-url>
cd phishwatcher

python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

Place the dataset CSV somewhere accessible, e.g. `data/raw/emails.csv`.

---

## Running the pipeline

The pipeline runs in four stages. Each stage persists its output, so later stages can be re-run independently once earlier ones have completed.

```bash
# 1. Parse the raw dataset and load it into SQLite
python -m src.data_pipeline.enron_processor --input data/raw/emails.csv --db data/emails.db

# 2. Build behavioural + stylometric profiles and the communication network
python -m src.behavioral_analysis.profile_builder --db data/emails.db
python -m src.behavioral_analysis.network_analyzer --db data/emails.db

# 3. Run the full offline evaluation (generates the impersonation test set,
#    scores every case with the ensemble, and reports metrics + plots)
python run_evaluation.py

# 4. Launch the interactive dashboard
python app/dashboard.py
```

> Adjust the exact CLI flags to whatever argument names exist in your checked-out version of each script — the commands above describe the pipeline stages, not a fixed interface contract.

`run_evaluation.py` writes:

- `results/roc_curve.png`
- `results/confusion_matrix.png`
- `results/threshold_analysis.png`
- a console summary of precision, recall, F1 and ROC-AUC at the default and optimal thresholds

## Using the dashboard

Once `python app/dashboard.py` is running, open `http://localhost:5000`.

From the dashboard you can:

1. **Analyse an email** — paste a sender, recipient(s), subject and body, and get back a composite anomaly score, a risk level, and a breakdown across the four component signals.
2. **Generate a test email** — use "Generate Normal" (a real historical email from a sender's own history) or "Generate Phishing" (a genuine style/behaviour-swapped impersonation case) to try the scorer without hand-crafting an example.
3. **Browse sender profiles** — page through per-sender behavioural baselines (recipient frequency, timing, language statistics) and inspect the communication network visualisation.

## Evaluation results

Results from a representative `run_evaluation.py` run against the generated impersonation test set:

| Metric | Value |
|---|---|
| ROC-AUC | 0.777 |
| F1-score (optimal threshold 0.35) | 0.654 |
| Recall @ optimal threshold | 85% |
| Confusion matrix @ default threshold (0.5) | TN 131 · FP 9 · FN 46 · TP 14 |

These figures support **RQ1** with a named caveat: the fused ensemble outperforms single-modal detection, but the current evaluation tooling cannot fully isolate the stylometric detector's standalone marginal contribution, so the "fusion beats single-modal" claim is supported rather than exhaustively proven. **RQ2** is currently supported by a working, low-latency demonstration and architectural reasoning (offline profile-building, lightweight online scoring) rather than a formally instrumented request-latency benchmark.

---

## Known limitations

- Evaluated on the Enron corpus, which does not contain genuine impersonation attempts — all positive test cases are constructed (style/behaviour/full swaps from real emails), not naturally occurring attacks.
- Stylometric population-level scoring (Isolation Forest) requires a minimum number of sender profiles to fit meaningfully; with very few profiles it falls back to a per-user z-score baseline only.
- RQ2's "near-real-time" claim rests on architecture and a working demo rather than a measured request-latency benchmark.
